Data Structures: Arrays, Linked Lists, Stacks, Queues, Hash Maps and Trees

Programming 101, Part 2

This post is about keeping the same data in memory in different shapes, and what that does to the cost of each operation. Searching a million records can take a microsecond in one layout and seconds in another. The language and the machine stay the same. The difference comes from how the data is laid out.

In an interview, “which data structure would you use?” really means: which operation will run most often, and what does it cost in this structure? Big O from part 1 is the measuring stick here. Below I go through arrays, linked lists, stacks, queues, hash maps and trees in order. At the end there is a comparison table and the questions that come up most in interviews.

1. What is a data structure?

A Data Structure is a way of organizing data in memory so that certain operations are fast. No structure is best at everything. One makes reads cheap and inserts expensive, another does the reverse.

The same books can be shelved in order, packed into boxes, or arranged with a catalog. Which one fits depends on how a book will be looked up later.

2. Arrays

An Array stores elements of the same type contiguously in memory. That is why the address of element i takes a single calculation: start + i × element_size. Access by index is O(1).

Numbered houses on a street work the same way. Nobody knocks on doors 1 to 6 to reach number 7. They go straight there.

#include <stdio.h>

int main(void) {
    int a[4] = {10, 20, 30, 40};
    for (int i = 0; i < 4; i++)
        printf("a[%d] = %d  address: %p\n", i, a[i], (void*)&a[i]);
    return 0;
}

An int is usually 4 bytes, so the addresses go up by 4. The output shows that the elements really sit next to each other.

The cost shows up in inserts and deletes. Adding or removing an element in the middle means shifting every element behind it by one, which is O(n). Searching an unsorted array is O(n) as well. If the array is sorted, binary search brings it down to O(log n).

Dynamic arrays

A C array has a fixed size. Python’s list, Java’s ArrayList and C++‘s vector are Dynamic Arrays. They keep an array inside, and when it fills up they allocate a larger one and copy everything over.

The copy takes O(n), but since capacity grows by a constant factor each time, it happens rarely. Over n appends the total number of copies stays proportional to n. That is why appending counts as amortized O(1).

A growing family that moves from a 4-person house to an 8-person house, then to a 16-person one, is a fair picture. Moving day is tiring, but the family does not move for every new child.

items = []
items.append(5)      # append: amortized O(1)
items.insert(0, 1)   # insert at front: O(n), everyone shifts
x = items[1]         # read by index: O(1)

3. Linked lists

In a Linked List, each element, called a node, holds a value and the address of the next node (a pointer). Nodes can be scattered across memory.

  • Singly linked: each node knows only the next one.
  • Doubly linked: each node knows both the previous and the next. The list can be walked backwards, and a known node can be deleted in O(1).

It works like a treasure hunt. Each clue gives the location of the next one. Reaching clue 5 means following the first four, but adding a new clue in between only takes changing one note.

class Node:
    def __init__(self, value, next=None):
        self.value = value
        self.next = next

head = Node(1, Node(2, Node(3)))     # 1 -> 2 -> 3
head.next = Node(9, head.next)       # 1 -> 9 -> 2 -> 3, O(1)

n = head
while n:                             # reaching element i: O(n)
    print(n.value); n = n.next

Inserting at the head, or after a node already in hand, is O(1). Finding that node, indexing and searching are O(n).

There is one more cost that Big O does not show: Cache Locality. The CPU pulls memory into its cache in small blocks. Reading one array element brings its neighbours into the cache too. Linked-list nodes each live somewhere else, so the cache misses often. For that reason arrays are usually faster in practice, even for operations with the same Big O.

4. Stacks

A Stack works as LIFO (Last In, First Out): the last element in is the first one out. Its operations are push (put on top), pop (take from the top) and peek (look at the top). All are O(1).

A pile of plates behaves the same way. The one on top is always taken first.

Where stacks are used:

  • Call stack: when a function is called, its frame is pushed onto the stack, and it is popped when the function returns. This is why infinite recursion ends in a “stack overflow” error.
  • Undo: the last action is the first one undone.
  • Bracket matching: a problem that comes up often in interviews.
def is_balanced(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for c in s:
        if c in "([{":
            stack.append(c)                      # push
        elif c in pairs:
            if not stack or stack.pop() != pairs[c]:
                return False                     # wrong or extra closer
    return not stack                             # nothing left open

print(is_balanced("{[()]}"))  # True
print(is_balanced("([)]"))    # False

In Python the end of a list is used as a stack. append and pop() are O(1).

5. Queues and deques

A Queue works as FIFO (First In, First Out): the first element in is the first one out. Enqueue adds at the back, dequeue removes from the front. Both are O(1).

A printer queue is an example. The document sent first is printed first.

Printer and job queues, message queues and the operating system’s ready queue all run on queues. BFS (Breadth-First Search), which walks a graph or tree level by level, uses one as well.

In Python, list.pop(0) is O(n), because every remaining element shifts one step left. For a queue, collections.deque is used:

from collections import deque

graph = {"A": ["B", "C"], "B": ["D"], "C": ["D"], "D": []}

def bfs(start):
    seen, queue = {start}, deque([start])
    while queue:
        node = queue.popleft()            # dequeue: O(1)
        print(node)
        for nb in graph[node]:
            if nb not in seen:
                seen.add(nb)
                queue.append(nb)          # enqueue: O(1)

bfs("A")  # A B C D

A Deque (Double-Ended Queue) adds and removes at both ends in O(1). It can be used as a stack or as a queue.

6. Hash maps

A Hash Map stores key -> value pairs. Python’s dict and Java’s HashMap are hash maps. Insert, lookup and delete are O(1) on average.

A Hash Function turns the key into a number. Taking that number modulo the array size gives a bucket index. So a hash map is a structure with an array inside. It converts the key into an index and uses the array’s O(1) access.

A coat check works the same way. A coat is handed over and ticket 42 comes back. To return it, nobody searches every hanger. They go straight to 42.

Collisions

Two different keys can land in the same bucket. This is called a Collision. There are two common fixes:

  • Chaining: each bucket holds a small list, and colliding entries are added to it. Java’s HashMap uses this method.
  • Open addressing: if the bucket is taken, the next free slot is found by a fixed rule. Python’s dict uses this method.
buckets = [[] for _ in range(8)]          # chaining

def put(key, value):
    i = hash(key) % len(buckets)          # key -> bucket index
    for pair in buckets[i]:
        if pair[0] == key:
            pair[1] = value; return       # update if present
    buckets[i].append([key, value])       # otherwise add to bucket

Load factor and resizing

Load Factor = number of entries / number of buckets. When this ratio crosses a threshold, the table roughly doubles and every entry is rehashed. In Java the default threshold is 0.75. A single resize takes O(n), but as with dynamic arrays the amortized cost is O(1).

Worst case

With a bad hash function, or when someone sends deliberately colliding keys, every entry piles into the same bucket. Lookup then becomes a scan of that list from start to end, which is O(n). Java 8 and later turn crowded buckets into trees (treeify), bringing this down to O(log n).

Keys have one more requirement: they must be immutable. A Python list cannot be a key. If a key’s hash changed later, the entry would be left in the wrong bucket.

7. Trees: binary trees, BSTs, heaps

A Tree is made of nodes branching out from a root, with no cycles. In a Binary Tree each node has at most two children. A family tree and the folders on a computer have the same shape.

Binary Search Tree (BST)

A BST (Binary Search Tree) has one rule for every node: values in the left subtree are smaller than the node, values in the right subtree are larger. Each step of a search discards half of what is left.

It resembles guessing a number between 1 and 100 from “higher” and “lower” answers. Each guess halves the range, and the number is found in at most 7 guesses.

class TreeNode:
    def __init__(self, v):
        self.v, self.left, self.right = v, None, None

def insert(root, v):
    if root is None: return TreeNode(v)
    if v < root.v: root.left = insert(root.left, v)
    else:          root.right = insert(root.right, v)
    return root

def search(root, v):
    while root and root.v != v:
        root = root.left if v < root.v else root.right
    return root is not None

root = None
for x in [50, 30, 70, 20, 40]: root = insert(root, x)
print(search(root, 40))  # True

Search, insert and delete take time proportional to the tree’s height, so O(h). In a balanced tree h ≈ log n and the cost is O(log n). If elements are inserted in sorted order (1, 2, 3, 4…), every node goes to the right and the tree degenerates into a linked list. The cost rises to O(n).

The fix is a balanced tree. AVL and Red-Black Trees perform rotations on each insert to keep the height at O(log n). Java’s TreeMap and C++‘s std::map are implemented as red-black trees. Also, walking a BST in-order (left, root, right) yields its elements sorted.

Heaps and priority queues

A Heap is a complete binary tree, usually stored inside an array. In a Min-heap every parent is smaller than its children, so the smallest element is always at the root. Looking at the root is O(1), while inserting and removing the minimum are O(log n). A Priority Queue is usually implemented with a heap.

The order in an emergency room is an example. The patient seen first is not the one who arrived first but the one whose condition is most urgent.

import heapq
h = []
for priority in [5, 1, 3]:
    heapq.heappush(h, priority)  # O(log n)
print(heapq.heappop(h))          # 1, the smallest: O(log n)

A heap is not sorted the way a BST is. It only guarantees that the smallest element is on top. Searching a heap for an arbitrary value is therefore O(n).

8. Which one when?

Structure Access by index Search Insert Delete Use it for
Array / dynamic array O(1) O(n) O(n), append amortized O(1) O(n), from end O(1) Frequent index reads, sequential scans
Linked list O(n) O(n) O(1)* O(1)* Frequent inserts and deletes at known spots
Stack none O(n) push O(1) pop O(1) Undo, call stack, brackets, DFS
Queue / deque none O(n) O(1) O(1) Job queues, BFS
Hash map none O(1) avg, O(n) worst O(1) avg O(1) avg Fast lookup by key, counting
BST (balanced) none O(log n) O(log n) O(log n) Ordered data, range queries
Heap min/max O(1) O(n) O(log n) min/max O(log n) Priority queues, top k

* When the position (node) is already in hand. Deleting in a singly linked list needs the previous node. In an unbalanced BST every operation degrades to O(n).

The choice comes down to the most frequent operation. Arrays fit access by index, hash maps fit lookup by key, and balanced trees fit ordered data. If the last element in should come out first, a stack is used. If the first element in should come out first, a queue is used.

Interview questions

1. What is the difference between an array and a linked list? An array sits in contiguous memory. Index access is O(1), inserting in the middle is O(n). In a linked list, inserting after a known node is O(1), while access and search are O(n). The pointers take extra memory and the structure is not cache-friendly. Common mistake: saying “linked list insertion is always O(1)”. Finding the spot first takes O(n).

2. Why is appending to a dynamic array counted as O(1)? When capacity runs out, the array grows by a constant factor and is copied. That expensive step is rare, so the total cost of n appends stays O(n). The cost per append is amortized O(1). Common mistake: reading amortized O(1) as “every single append is O(1)”.

3. How does a hash map work, and why is its worst case O(n)? A hash function maps the key to a bucket index. Collisions are handled by chaining or open addressing, and the table grows when the load factor crosses its threshold. If every key lands in one bucket, lookup turns into a linear scan. Common mistake: saying “hash maps are always O(1)”, or not mentioning collisions at all.

4. What is the difference between a stack and a queue? Give an example of each. A stack is LIFO (undo, call stack, DFS). A queue is FIFO (printer queue, BFS). Both have O(1) core operations. Common mistake: writing a Python queue with list.pop(0). That is O(n), and deque should be used.

5. How do you check whether the brackets in an expression are balanced? Opening brackets are pushed onto a stack. On each closer, the expression is unbalanced if the stack is empty or the top does not match. At the end the stack must be empty. Time is O(n). Common mistake: only comparing the number of openers and closers. ([)] passes that test but is not balanced.

6. Is BST search always O(log n)? No, it is O(h). In a balanced tree h ≈ log n. A BST built from sorted input turns into a linked list and costs O(n). AVL and red-black trees keep the height at O(log n). Common mistake: saying “BST = O(log n)” without mentioning balance.

7. Hash map or balanced tree (dict or TreeMap)? If only lookup by key is needed, a hash map (O(1) average). If ordered iteration, the minimum or maximum, or range queries such as “between 10 and 20” are needed, a balanced tree (O(log n)). Common mistake: assuming a hash map keeps its keys sorted.

8. How do you find the 10 largest numbers among a million? Keep a min-heap of size 10. If a new number is larger than the top, the top is removed and the new number is pushed. The cost is O(n log k) with k = 10. Sorting the whole list would be O(n log n). Common mistake: using a max-heap, or sorting the whole list without thinking.
